# Story 12.14 — NFR-assessment

Scope: frontend-only bugfix, `apps/web/src/components/review/MobileReviewDeck.tsx` + `ArtworkReviewItemCard.tsx` (comment-only). Backend ongemoeid.

| NFR | Verdict | Onderbouwing |
|-----|---------|---------------|
| Performance | PASS | Alleen twee extra `Record<string, …>` state-maps (`pendingRel`, per-item, al bestaand patroon zoals `assignedCode`/`decisions`) — O(1) lookups/updates, geen nieuwe loops over de queue (max ~enkele tientallen items per sessie). Geen extra renders buiten de bestaande her-render-cyclus bij state-wijziging. |
| Security | PASS | Geen nieuwe endpoints, geen secrets. De `code`-waarde komt uit een gesloten lijst (`codes` = vaste keurmerk-code-universe + queue-codes), nooit vrije tekstinvoer die naar de server gaat als ongevalideerde payload — ongewijzigd t.o.v. bestaand `relabel`-pad. `rel` blijft een fractie-bbox (x/y/width/height), zelfde vorm als voorheen. |
| Betrouwbaarheid / graceful degradation | PASS | Alle nieuwe branches lopen door de bestaande `try/catch` → `message.error('review.actionError')`-afhandeling in `applyAnnotation`/`relabel`/`applyDecision`/`commitReject`; geen nieuw foutpad geïntroduceerd. De CR-fix (stale `pendingRel`/`assignedCode` opruimen bij beslissingswissel) verbetert de betrouwbaarheid van de gecombineerde registratie (voorkomt silent data-mismatch tussen getoonde UI-status en geregistreerde referentie). |
| Toegankelijkheid | PASS | Geen nieuwe interactieve elementen buiten de al-bestaande AntD `Button`/`Drawer`/`Input.Search`-patronen (zelfde compliant componenten als de rest van het deck). De nieuwe succesmelding gebruikt het bestaande `message.success`-kanaal (tekst + kleur, geen kleur-only signaal). |
| Concurrency/idempotency | PASS | Elke actie is gepoortwacht door de bestaande `busy`-vlag (`if (!cur || busy) return`); geen nieuwe race-conditie geïntroduceerd. `pendingRel`/`assignedCode`-updates gebruiken functionele `setState`-updaters (geen stale-closure-risico). |
| Onderhoudbaarheid | PASS | Wijzigingen volgen het bestaande component-patroon (per-item `Record`-state, dezelfde `useCallback`-structuur, dependency-arrays correct bijgewerkt met `assignedCode`/`pendingRel`). Uitgebreide inline comments leggen de Story 12.14-rationale vast op elke wijzigingslocatie. |

**Verdict: PASS op alle toepasselijke NFR's.** Geen findings die verdere actie vereisen.
