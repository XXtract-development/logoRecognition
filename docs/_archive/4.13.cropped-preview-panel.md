# Story 4.13: Cropped Preview Panel

## Status
Draft

## Story
**As a** Data Manager (Jan),
**I want** automatic cropped logo previews of all bounding boxes in a right panel,
**so that** I can directly verify which logos are correctly selected before categorizing them.

## Acceptance Criteria
1. Automatic preview generation - When bounding box is created, cropped preview immediately appears in right panel
2. Real-time preview updates - Preview updates in real-time when bounding box is resized or moved
3. Right panel layout - Fixed width (300px) panel with scrollable preview list and standardized card sizes
4. Preview card information - Each card shows cropped image, bounding box ID, coordinates, and delete button
5. Bidirectional synchronization - Click on preview selects canvas bounding box, delete works from both sides
6. Hover highlighting - Hover on preview highlights corresponding bounding box on canvas
7. Performance optimization - Preview generation completes within 100ms with lazy loading for off-screen previews
8. Empty and error states - Friendly messages for no previews, loading states, and retry functionality for failures
9. Quality preservation - Previews maintain sharp quality and original aspect ratio within standardized dimensions

### Performance Requirements
[Source: architecture/15-security-and-performance.md#performance-optimization]

#### Generation Performance
- **Speed**: Preview generation completes within 100ms per bounding box
- **Quality**: Use high-quality canvas rendering (imageSmoothingQuality: 'high')
- **Memory**: Limit preview cache to 50MB, implement LRU eviction
- **Debouncing**: 150ms debounce for bounding box resize operations
- **Threading**: Use Web Workers for CPU-intensive cropping operations

#### Rendering Performance
- **Lazy Loading**: Implement virtual scrolling for lists >20 previews
- **Image Optimization**: Generate WebP format with JPEG fallback
- **Caching Strategy**: Cache generated previews with weak references
- **Memory Cleanup**: Automatically revoke blob URLs when previews are removed
- **Intersection Observer**: Load previews only when entering viewport

### Error Handling Strategy
[Source: architecture/18-error-handling-strategy.md#frontend-error-handling]

#### Preview Generation Errors
1. **Invalid Coordinates**: Clamp coordinates to image boundaries
2. **Canvas Context Error**: Fallback to placeholder image with retry option
3. **Memory Limit**: Show memory warning, enable cleanup mode
4. **Image Load Error**: Display error state with manual retry button
5. **Performance Degradation**: Switch to lower quality mode automatically

#### User Experience During Errors
- **Non-blocking**: Errors don't prevent continued annotation work
- **Visual Feedback**: Clear error indicators with specific error messages
- **Recovery Actions**: Always provide retry or alternative options
- **State Preservation**: Maintain working previews when some fail

describe('PreviewPanel', () => {

    const mockCanvas = document.createElement('canvas');

    });

    fireEvent.click(getByTestId('preview-card-box-1'));

      expect(getByTestId('canvas-annotation-box-1')).toHaveClass('selected');
    });
  });
});
