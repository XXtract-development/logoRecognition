# Story 4.12: Detection Modes (Smart & Manual)

## Status
Draft

## Story
**As a** Data Manager (Jan),
**I want** to choose between automatic logo detection and manual selection modes,
**so that** I can efficiently and accurately annotate logos depending on the complexity and situation.

## Acceptance Criteria
1. Mode toggle switch - Toggle switch at top of interface: "Smart Detection" ⭄ "Manual Mode"
2. Default smart mode - Default mode is "Smart Detection" with clear visual indicator
3. Smart click interaction - Single click on image triggers automatic boundary detection with loading indicator
4. Detection preview display - Detected boundary shown as preview with confidence score and accept/reject options
5. Manual drawing mode - Click and drag to draw rectangle with real-time preview and minimum size enforcement
6. Automatic fallback handling - Low confidence (<60%) automatically falls back to manual with clear messaging
7. Error recovery - API errors gracefully fall back to manual mode with retry option
8. Mode persistence - Selected mode persists throughout annotation session
9. Success state management - Accepted boundaries convert to standard bounding boxes with proper styling

### Error Handling Strategy
[Source: architecture/18-error-handling-strategy.md#frontend-error-handling]

#### Fallback Scenarios
1. **Low Confidence (<60%)**: Automatic fallback to manual with user notification
2. **API Timeout (>2s)**: Show timeout message, enable retry, switch to manual
3. **Network Error**: Graceful degradation to manual-only mode
4. **Server Error (5xx)**: Display error message, offer retry, enable manual fallback
5. **Invalid Response**: Log error, show generic failure message, fallback to manual

#### User Experience During Errors
- **Non-blocking**: Errors don't prevent continued annotation in manual mode
- **Clear Messaging**: Specific error messages with suggested actions
- **Recovery Options**: Always provide path forward (retry, manual mode, skip)
- **State Preservation**: Maintain user's work and context during error recovery

### Performance Requirements
[Source: architecture/15-security-and-performance.md#performance-optimization]

- **API Response Time**: Smart detection completes within 2 seconds
- **UI Responsiveness**: Mode switching < 100ms, manual drawing at 60fps
- **Memory Management**: Clean up event listeners and timeouts
- **Debouncing**: Prevent rapid API calls from quick successive clicks
- **Caching**: Cache detection results for identical click coordinates
