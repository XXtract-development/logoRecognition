# Story 4.14: Category & Value Management

## Status
Draft

## Story
**As a** Data Manager (Jan),
**I want** to assign categories and values to each cropped logo preview,
**so that** I can prepare properly labeled training data for the machine learning model.

## Acceptance Criteria
1. Category selection interface - Each preview card has category dropdown with autocomplete and existing categories
2. Value input interface - Value input field appears after category selection with autocomplete suggestions
3. Quick category addition - "Add new category" functionality with inline modal and validation
4. Category-value pairing - System stores and validates unique category-value combinations
5. Visual state management - Incomplete cards show warning indicators, complete cards show success indicators
6. Progress tracking - Progress indicator shows "X of Y logos categorized" with continue button
7. Real-time validation - Form validation prevents empty values and duplicate combinations
8. Suggestion system - Autocomplete based on historical usage and common values for each category
9. Offline capability - LocalStorage fallback when API is unavailable with sync when restored

#### Data Model Requirements
```typescript
interface Category {
  id: string;
  name: string;
  description?: string;
  usageCount: number;
  createdAt: Date;
  createdBy: string;
  isDefault: boolean;
}

interface CategoryValue {
  id: string;
  categoryId: string;
  value: string;
  usageCount: number;
  lastUsed: Date;
  aliases?: string[];
}

interface LogoAnnotation {
  id: string;
  previewId: string;
  boundingBoxId: string;
  category: Category | null;
  value: CategoryValue | null;
  confidence?: number;
  isComplete: boolean;
  lastModified: Date;
}

interface AnnotationState {
  annotations: LogoAnnotation[];
  categories: Category[];
  values: CategoryValue[];
  suggestions: Record<string, CategoryValue[]>;
  progress: {
    completed: number;
    total: number;
    canContinue: boolean;
  };
}
```

### Form Validation Strategy
[Source: architecture/17-coding-standards.md#validation-patterns]

#### Client-Side Validation
1. **Category Name**: Required, unique, 1-50 characters, alphanumeric with spaces
2. **Category Description**: Optional, max 200 characters
3. **Value Input**: Required after category selection, 1-100 characters, no duplicates
4. **Real-time Feedback**: Immediate validation on field blur and form submission
5. **Visual Indicators**: Error highlighting, success confirmation, loading states

#### Server-Side Integration
- **API Validation**: Backend enforces same validation rules
- **Conflict Resolution**: Handle category/value conflicts gracefully
- **Error Mapping**: Map API errors to specific form fields
- **Optimistic Updates**: Show immediate feedback, rollback on server errors

### Performance Requirements
[Source: architecture/15-security-and-performance.md#performance-optimization]

#### Response Time Targets
- **Category Dropdown Load**: < 200ms for initial categories
- **Value Suggestions**: < 100ms after category selection
- **Form Validation**: < 50ms for immediate feedback
- **Autocomplete Search**: < 150ms for filtered results
- **Progress Updates**: < 100ms for state changes

#### Optimization Strategies
- **Memoization**: Use React.memo for category and value components
- **Debouncing**: 300ms debounce for autocomplete searches
- **Caching**: Cache category/value data with 10-minute TTL
- **Virtual Scrolling**: For large category/value lists (100+ items)
- **Lazy Loading**: Load value suggestions only when category is selected

### Offline Strategy
[Source: architecture/10-frontend-architecture.md#offline-capabilities]

#### LocalStorage Fallback
1. **Category Storage**: Cache categories in localStorage with timestamps
2. **Annotation Backup**: Store incomplete annotations locally
3. **Sync Detection**: Monitor online/offline status
4. **Conflict Resolution**: Merge local changes with server data on reconnection
5. **User Feedback**: Clear indicators of offline mode and pending sync

#### Data Synchronization
- **Background Sync**: Automatically sync when connection restored
- **Conflict Handling**: Server-side timestamp wins, user notified of conflicts
- **Partial Sync**: Sync individual categories/annotations independently
- **Recovery**: Robust recovery from partial sync failures
